## 数据接口和目录管理

数据/split/transform 统一为 schema 2.0.0，冻结 data_version 与 split_id。预测均有稳定 sample_id、原强度/log10 输出、方法/run 身份和失败状态。CNN 额外交付 normalized 与 transform_id；直接 log10 模型留空这两列。热力学保留 Tx_rate，并由 train 校准后进入强度比较。区域表采用局部 0 起始、右端不包含的坐标；推定和缺失状态独立记录，不替换主表。

| 目录 | 职责 | 使用规则 |
|---|---|---|
| data/ | 原始输入、冻结主表、划分与变换 | 改样本/标签/划分必须另发版本 |
| configs/ | 数据来源配置、整合实验计划 | 新实验用 new-run 生成新名字 |
| pr02/ | 数据处理、五方法调度、评测、发布与验收 | 根目录统一 CLI |
| CNN/、Ridge/、KNN/、thermo/ | 各方法代码、特征和历史入口 | 当前模型身份由配置和 results 指定 |
| analysis_m2m3/ | EDA、区域、误差和案例 | 每图必须有源表、样本数和运行记录 |
| runs/、CNN/runs/ | 不覆盖的模型和分析运行 | 只有被验收并显式登记的运行属于交付 |
| results/ | 唯一当前成绩和模型预测索引 | 通过 publish 更新 |
| reports/ | 状态、报告、验收与日志 | 新审查有新日期，不改写旧证据 |
| history/ | 复现必需的原交付 ZIP 和恢复指引 | 旧重复产物从 Git 历史或 D 盘归档恢复 |

老师给出的 data/preprocessing/models/experiments/results 结构职责已由以上目录承担。本次补上缺失的数据处理入口和结构说明，暂不搬动所有方法目录：模型、图表和哈希记录绑定现有路径，整体改名没有中期收益。
